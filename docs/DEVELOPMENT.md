# Разработка и локальный запуск

## Ограничения

- Работать только внутри папки проекта.
- Использовать HTML, CSS и JavaScript без сторонних библиотек.
- Сохранять текущую структуру простого статического сайта.
- Не удалять рабочие механики без прямой просьбы пользователя.
- Не изменять публичный адрес без прямой просьбы пользователя.
- Не добавлять секреты в файлы проекта или историю Git.
- При каждом изменении проекта обязательно обновлять корневой `CHANGELOG.md`.

## Локальный запуск

Игра является статическим сайтом. Рекомендуется запускать её через локальный HTTP-сервер.

Пример:

```text
python -m http.server 4173 --bind 127.0.0.1
```

Локальный адрес:

```text
http://127.0.0.1:4173/
```

## Типовой процесс изменения

1. Прочитать `AGENTS.md` и тематическую документацию.
2. Проверить текущее состояние файлов.
3. Внести минимально необходимые изменения.
4. Обновить соответствующий раздел документации.
5. Добавить запись об изменении в раздел `В разработке` файла `CHANGELOG.md`.
6. Проверить синтаксис JavaScript.
7. Запустить автоматические тесты.
8. Выполнить сборку.
9. Проверить изменённое поведение в браузере.
10. Убедиться в отсутствии ошибок консоли.
11. При необходимости обновить существующий публичный сайт.

## Команды

Автоматические тесты:

```text
npm test
```

Сборка:

```text
npm run build
```

Если `npm` недоступен, соответствующие файлы можно запускать напрямую через Node.js:

```text
node test-game.cjs
node build.mjs
```

## Работа с документацией

При изменении проекта необходимо обновлять соответствующий файл:

- механика — `RULES.md`;
- меню — `INTERFACE.md`;
- управление — `CONTROLS.md`;
- структура — `TECHNOLOGY.md`;
- оформление — `VISUAL_STYLE.md`;
- музыка и звук — `AUDIO.md`;
- проверки — `TESTING.md`;
- публикация — `DEPLOYMENT.md`.

## Ведение истории изменений

Любое изменение проекта должно сопровождаться обновлением `CHANGELOG.md` в том же наборе правок.

Новые записи добавляются в раздел `В разработке`:

- новые возможности — `Добавлено`;
- изменение существующего поведения — `Изменено`;
- исправления ошибок — `Исправлено`;
- удалённые возможности — `Удалено`;
- изменения безопасности — `Безопасность`.

Запись должна кратко описывать результат для пользователя или разработчика. Не добавлять в changelog секреты, временные токены и внутренние данные авторизации.
